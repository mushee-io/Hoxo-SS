# M58 independent transaction-to-receipt binding

The read-only audit must not treat a successful transaction at the same ledger as proof of settlement. `getTransaction(hash)` must independently decode transaction-local Soroban contract events into `contractEvents: [{ contractId, type: 'settled', txHash, ledger, matchId, makerSide }]`. Only an event emitted by the exact verified M9 contract with the exact match ID and side qualifies. Missing or malformed event evidence fails closed. The adapter must derive events from authentic finalized Testnet RPC transaction metadata, not user-provided claims, indexer guesses, or a separate contract read. The contract `receipt` and `is_settled` read calls are additional evidence, not replacements for the transaction-local event.

This is a strict adapter contract; do not infer that Stellar RPC exposes these normalized fields directly. Implement and independently test the native XDR decoder against actual M9 event schema before asserting production readiness. No signed BUY/SELL settlement receipt has yet been independently established. Different G-addresses alone cannot prove different beneficial owners, so the audit never certifies organic trading volume. No signing, submission, mainnet activity, or automatic contract administration is authorized by this change.

## M58 event identity guard

The adapter must preserve the event's own canonical transaction hash and ledger from the finalized RPC transaction. The audit now requires both to match the independently fetched transaction; missing, string-coerced or substituted event identity fails closed. These are normalized adapter fields, **not** assertions about the raw Stellar RPC JSON shape. Tests deliberately mutate the event hash and ledger without altering the successful transaction. The adapter must still be independently validated against authentic Soroban XDR before any actual on-chain settlement is certified.
